# v0.1.21 — Correct cached-context accounting on ACP 1.5.0

## Fix

- Stop subtracting cache-read tokens from already-correct ACP 1.5.0 single-inference context updates. The reported context now remains 26,947 tokens instead of being reduced to 2,405 in the regression reported in [#80](https://github.com/zacbemis/pi-antigravity-acp-provider/issues/80).
- Preserve the legacy duplicate-cache correction only when a single inference's reconciled prompt total demonstrates the exact discrepancy. Keep aggregate token/cost accounting separate from current context occupancy.
- Add regression fixtures replaying the reported ACP 1.4.3 and 1.5.0 counters across cached, multi-step and single-inference turns. Check Pi's actual context estimator and next-request output clamp, aggregate counters and reference costs.

## Validation and limitations

- Typechecking and **461 ordinary tests** pass; eight opt-in official-runtime/live tests remain skipped.
- Release validation includes a clean install, package dry runs, isolated packed-install smoke tests and a full dependency audit. CI checks Node 22.19.0 and 24; packaging is also exercised with npm 12.
- No fresh authenticated inference or independent live-server capture was performed. Legacy multi-inference updates can still overestimate context because the final inference's cache split is unavailable; #80 remains open for that limitation and live verification.

Pi 1.5.x support, ACP protocol 1, permission defaults and the signed runtime catalog are unchanged. Reference costs are estimates, not Antigravity subscription charges.
