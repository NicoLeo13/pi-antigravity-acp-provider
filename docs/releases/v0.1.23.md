# v0.1.23 — Private profiles and cleaner workspaces

- Isolate Google authentication and ACP state per Pi profile in a private, file-backed store. Account switching no longer uses another Antigravity client's credentials or the shared macOS Keychain entry. [#112](https://github.com/zacbemis/pi-antigravity-acp-provider/pull/112)
- Keep throwaway model-discovery, quota, login, and API-key-check sessions out of project working directories. [#117](https://github.com/zacbemis/pi-antigravity-acp-provider/pull/117)
- Disable native `run_workflow` by default through Antigravity's session tool filter, preventing its generated `skills/system/run-workflow/SKILL.md` from appearing in projects on supporting runtimes. Set `"nativeWorkflows": true` in the provider's `config.json` and restart Pi to opt in. Chat sessions retain the project working directory; existing skill files are never deleted by the provider. [#122](https://github.com/zacbemis/pi-antigravity-acp-provider/pull/122)
- Autocomplete canonical subcommands and option values under `/antigravity-acp`, including `doctor --verbose`, without adding top-level slash-command aliases. [#123](https://github.com/zacbemis/pi-antigravity-acp-provider/pull/123)
- Update compatible dependencies, including ACP SDK 2.8.0. [#115](https://github.com/zacbemis/pi-antigravity-acp-provider/pull/115)

## Upgrade notes

Sign in again with `/login antigravity-acp` after upgrading from the shared credential store. Each Pi profile now has its own login. The old store remains untouched, and its settings, hooks, skills, and ACP conversations are not migrated. Reconfigure anything needed in the new profile. Pi chat history is unchanged.

Older manually managed ACP runtimes may ignore the `disabledTools` metadata and continue generating the workflow skill. Existing generated files are left untouched.
